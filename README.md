# Today Planner — 오늘을 위한 작은 습관

오늘 반드시 끝내야 할 일을 한눈에 보여주고, 가장 중요한 업무부터 처리하도록 돕는
모던한 개인 업무 대시보드입니다. HTML5 · CSS3 · Vanilla JavaScript로만 제작되었고,
백엔드 없이 브라우저에서 바로 실행되며 모든 데이터는 LocalStorage에 저장됩니다.
접속 시 간단한 로그인 잠금을 거쳐 대시보드로 진입합니다(아래 [Login](#login) 참고).

## 실행 방법

`index.html`을 브라우저에서 열면 됩니다. 빌드 과정이나 서버가 필요 없습니다.
(모든 스크립트는 클래식 스크립트이며 외부 네트워크 요청이 없어 `file://` 에서도 동작합니다.)

## Login

이 프로젝트는 DB 없이 클라이언트 측에서 동작하는 간단한 로그인 기능을 제공합니다.
접속하면 대시보드보다 먼저 로그인 화면이 표시되고, 설정된 아이디·비밀번호가 일치할
때만 대시보드가 초기화·표시됩니다. 로그인하지 않은 상태에서는 새로고침하거나 페이지를
직접 열어도 대시보드 내용이 노출되지 않습니다.

- **인증 상태 저장**: 기본은 `sessionStorage` 이며, "로그인 상태 유지"를 체크하면
  `localStorage` 를 사용합니다. 저장 키(`todayPlannerAuthenticated`,
  `todayPlannerRemembered`)는 플래너 데이터 키(`today-planner:v1`)와 분리되어 있어
  기존 할 일·일정·메모에 영향을 주지 않습니다. 실제 비밀번호는 어디에도 저장하지
  않습니다.
- **로그아웃**: 설정 화면의 "계정 → 로그아웃"에서 처리합니다. 인증 정보를 지우고
  페이지를 다시 불러와 로그인 화면으로 돌아갑니다(뒤로가기로도 대시보드가 다시
  노출되지 않음). 저장된 할 일·일정·메모는 그대로 유지됩니다.
- **관리자 계정 변경**: `js/auth.js` 상단 `AUTH_CONFIG` 의 해시 값을 교체합니다.
  비밀번호는 평문이 아니라 `TP.auth._hash("...")` 로 만든 해시로 보관합니다.
  (브라우저 콘솔에서 `TP.auth._hash("새-비밀번호")` 를 실행해 값을 얻을 수 있습니다.)

> **주의**: 본 인증 방식은 실제 보안 인증 시스템이 아니며, 코드가 모두 브라우저에서
> 실행되므로 개인용 접근 제한 용도로만 사용해야 합니다. 관리자 계정 정보는 이
> 문서에 기록하지 않습니다.

## 파일 구조

```
index.html          앱 셸(사이드바 / 모바일 상단바 / 메인 영역)
css/styles.css       디자인 토큰, 라이트·다크 테마, 반응형 레이아웃 전부
js/
  utils.js           순수 헬퍼 (날짜/시간 포맷, debounce, DOM 헬퍼,
                     반복일 계산, 마감 상태 판정 등) — 상태 없음
  store.js           단일 상태 저장소. LocalStorage 방어적 파싱/정규화,
                     CRUD, 자정/재접속 롤오버, 최근 7일 히스토리, 파생 셀렉터,
                     반복 업무 다음 회차 생성, 백업 JSON 래핑/검증
  ui.js              재사용 UI 프리미티브: modal/drawer, confirm(), toast()
                     (포커스 트랩, ESC 닫기, 스크롤 잠금, 포커스 복원 포함)
  calendar.js        독립형 미니 월간 캘린더 컴포넌트
  views.js           화면 렌더링 + 할 일/일정 입력 모달(유효성 검사)
  auth.js            클라이언트 측 로그인 잠금(로그인 화면 제어, 인증 상태,
                     세션/영구 저장 선택, 로그아웃) — app.js는 로그인 이후에만 초기화
  app.js             부트스트랩, 해시 라우팅, 실시간 시계, 테마, 모바일 내비게이션
```

### 기능과 UI의 분리

- **데이터/로직**은 `store.js` 안에만 있습니다. 모든 변경은 `TP.store`의 메서드를
  거치고, 변경 후 `tp:change`(메모 자동 저장은 `tp:note`) DOM 이벤트를 발생시킵니다.
- **UI**는 그 이벤트를 구독해 현재 화면만 다시 그립니다. 포커스를 뺏으면 안 되는
  영역(대시보드 빠른 메모 등)은 부분 렌더러로 처리합니다.
- 공통 UI 조각(모달·확인창·토스트)은 기능을 모르는 순수 컴포넌트입니다.

## 데이터 구조 (LocalStorage 키: `today-planner:v1`)

```jsonc
{
  "version": 1,
  "tasks": [
    { "id": "...", "title": "", "priority": "top|high|normal",
      "done": false, "due": "HH:MM", "note": "",
      // 반복 업무 (Phase 1). 예전 데이터에는 없을 수 있으며 이 경우
      // recurrence="none", recurrenceId="", nextOccurrence="" 로 안전하게 보정됩니다.
      "recurrence": "none|daily|weekdays|weekly|monthly",
      "recurrenceId": "",          // 같은 반복 체인을 묶는 id
      "nextOccurrence": "YYYY-MM-DD",  // 다음 회차 예정일(있을 때만)
      "createdAt": "ISO", "completedAt": "ISO|null" }
  ],
  "events": [
    { "id": "...", "title": "", "date": "YYYY-MM-DD",
      "start": "HH:MM", "end": "HH:MM", "place": "", "memo": "" }
  ],
  "notes": "",
  "noteSavedAt": "ISO|null",
  "history": { "YYYY-MM-DD": { "completed": 0, "total": 0 } },
  "lastActiveDate": "YYYY-MM-DD",
  "settings": { "theme": "light|dark" }
}
```

### 방어 코드 (Robustness)

- 파싱 실패 시 `try/catch`로 안전하게 기본값으로 초기화합니다.
- 모든 배열 항목을 정규화하며, 제목이 없는 항목·잘못된 우선순위·비정상 날짜/시간
  문자열은 걸러내거나 기본값으로 보정합니다.
- 저장 실패(용량 초과 등)는 토스트로 사용자에게 알립니다.
- **자정 롤오버**: `lastActiveDate`가 오늘과 다르면 지난날의 완료율을 히스토리에
  기록하고, 완료된 할 일은 정리하고 미완료 항목은 오늘로 이월합니다. 1초 간격 타이머와
  탭 복귀(`visibilitychange`) 시 모두 검사합니다.

## 접근성

## Phase 1 기능

### 🔍 업무 검색 및 필터 (할 일 관리)

- 검색창에 입력하면 제목·메모에 검색어가 포함된 할 일만 실시간으로 표시됩니다.
  새로고침은 필요 없고, 입력 중에도 검색창 포커스가 유지됩니다.
- 필터: **전체 / 미완료 / 완료 / 최우선 / 중요 / 일반 / 오늘 / 마감 임박**.
  검색어와 필터는 동시에 적용됩니다(예: "보고서" + "미완료").
- 조건에 맞는 항목이 없으면 “검색 결과가 없습니다.” 안내를 보여줍니다.

### ⏰ 마감 임박 표시

이 앱의 할 일은 모두 “오늘” 항목이므로 마감 시각(`due`, HH:MM)을 기준으로
상태를 자동 판정합니다.

| 상태 | 배지 | 기준 |
| --- | --- | --- |
| 마감 | 🔴 마감 | 마감 시각이 지남 |
| 마감 임박 | 🟡 마감 임박 | 마감까지 60분 이내 |
| 오늘 마감 | 🟠 오늘 마감 | 오늘 마감 시각이 있고 60분 초과 |
| 예정 | 🔁 M/D 예정 | 반복으로 만들어진 다음 회차(미래일) |

대시보드의 최우선/할 일 목록은 `마감 → 마감 임박/오늘 마감 → 우선순위 → 마감 시각`
순으로 정렬됩니다. 경고색은 배지와 왼쪽 테두리 한 줄로만 절제해서 사용합니다.

### 🔁 반복 업무

할 일 모달에서 **반복 안 함 / 매일 / 평일 / 매주 / 매월** 중 선택합니다(기본값: 반복 안 함).

- 반복 할 일을 **완료**하면 그때 다음 회차가 한 번 생성됩니다.
- 같은 반복 체인(`recurrenceId`)에 미완료 항목이 이미 있으면 새로 만들지 않으므로,
  새로고침하거나 완료를 껐다 켜도 중복 생성되지 않습니다.
- 평일은 토·일을 건너뛰고, 매주는 7일 뒤, 매월은 같은 날짜(짧은 달은 말일로 보정)를
  다음 회차 예정일로 계산합니다.
- 목록에서는 `🔁 매일` 같은 배지로 표시됩니다.
- 반복 필드가 없는 예전 데이터도 안전하게 기본값으로 처리됩니다.

### 💾 데이터 백업 / 복원 (설정 › 데이터 관리)

- **📥 데이터 내보내기**: 현재 LocalStorage 데이터를 `today-planner-backup-YYYY-MM-DD.json`
  파일로 저장합니다. 형식은 `{ "app": "Today Planner", "version": 1, "exportedAt": "...",
  "data": { tasks, events, notes, history, settings, ... } }` 로, 할 일·일정·메모·테마·
  통계 히스토리 등 주요 사용자 데이터를 모두 포함합니다.
- **📤 데이터 가져오기**: JSON 파일을 고르면 “현재 데이터가 백업 파일의 데이터로
  변경됩니다. 계속하시겠습니까?” 확인을 거쳐 복원하고 “데이터가 성공적으로
  복원되었습니다.” 를 표시한 뒤 화면을 다시 그립니다. 잘못된 JSON이나 Today Planner
  백업이 아닌 파일은 “잘못된 백업 파일입니다.” 안내만 띄우고 앱은 그대로 유지됩니다.
  (예전 형식의 순수 상태 JSON도 호환됩니다.)
- **🗑 전체 데이터 삭제**: 되돌릴 수 없다는 경고 확인 후 초기 상태로 되돌립니다.
  로그인 인증 키(`todayPlannerAuthenticated` 등)는 플래너 데이터와 분리되어 있어
  삭제되지 않습니다.

> **백업 권장**: 모든 데이터는 이 브라우저의 LocalStorage에만 저장됩니다. 브라우저
> 데이터(사이트 데이터/캐시)를 지우면 사라질 수 있으니 **정기적으로 ‘데이터
> 내보내기’로 백업**해 두세요.
